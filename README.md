# 🎵 晨读歌单 · 微信扫码点歌

英语早读前放什么歌？同学们**用微信扫一下**就能匿名写下想听的歌，给喜欢的歌点赞，点赞多的排在前面。

- **零门槛：不用注册、不用登录、不用关注公众号、不用小程序**，扫码 → 填歌名 → 提交，三步结束
- 只收 **歌名 + 歌手**，没有留言栏，符合"就收集想听的歌"
- 匿名：投稿只显示「匿名 #A3F」，服务端不记录姓名、手机号，IP 也不入库

> 为什么不需要注册：这个工具压根没有账号系统。所谓"匿名编号"是提交时随机生成的显示标签；
> 浏览器自己会生成一个随机设备号（只用来防止同一台手机重复点赞），学生对它完全无感。
>
> 需要注册账号的是**你**（GitHub + Render 用来托管网站），学生那边什么都不用办。

---

## 为什么微信扫码能直接用

| 关键点 | 这里的做法 |
| --- | --- |
| 微信对 http 链接会警告甚至拦 | 部署在 Render 上自带 **HTTPS** 证书；服务端还会把误贴的 http 链接自动 301 跳到 https |
| 微信内置浏览器内核较旧 | 页面没用花哨特性，加了 `-webkit-` 前缀和降级写法，老安卓微信也不白屏 |
| 需要登录 / 关注才能用 | 完全不需要，打开就能投 |
| 微信缓存页面 | 页面响应设了 `no-cache`，从后台切回来会自动刷新数据 |

## 上线：3 步，约 5 分钟（免费）

### 第 1 步：代码放到 GitHub

不用装 git，浏览器就行：

1. 打开 <https://github.com/new>，仓库名填 `song-box`，选 **Public**，Create
2. 点 **uploading an existing file**
3. 把 **song-box 文件夹里的内容**全部拖进去（`server.js`、`lib/`、`public/`、`package.json`、`render.yaml`），别拖外层文件夹
   - `data/` 可以跳过，里面只是我放的演示数据
4. Commit changes

### 第 2 步：Render 一键部署

1. 打开 <https://render.com>，用 GitHub 账号注册（免费，不用绑卡）
2. **New +** → **Blueprint** → 选 `song-box` 仓库 → **Apply**
3. 等 2～3 分钟，得到 `https://song-box-xxxx.onrender.com` —— **这个就是给微信扫的地址，自带 https**

> 不走 Blueprint 也行：**New +** → **Web Service** → 选仓库 →
> Build `npm install --omit=dev`，Start `node server.js`，Plan 选 Free。

### 第 3 步：别让数据丢（强烈建议）

Render 免费实例闲置后会休眠，**休眠会清空磁盘**，投稿就没了。接个免费 Redis 就永久保存：

1. <https://upstash.com> 注册 → **Create Database** → 免费套餐，区域选 **Singapore**（离国内近）
2. 复制详情页 REST API 的 `UPSTASH_REDIS_REST_URL` 和 `UPSTASH_REDIS_REST_TOKEN`
3. Render → 你的服务 → **Environment** → 加这两个变量 → Save（自动重启）

> ⚠️ 注册 Upstash 时**不要添加付款方式**。按他们的规则，账号一旦绑卡，免费数据库会自动转成按量付费。
> 不绑卡就永远是免费档，用超了会被限流，而不是扣钱。

### 到底花不花钱

**全程 0 元**，而且不绑卡就不会产生任何费用：

| 项目 | 免费额度 | 这个用法的消耗 |
| --- | --- | --- |
| 代码 | MIT，零依赖 | — |

### 拿到网址后，先做这个微信自测（1 分钟）

1. 打开 `https://你的域名/admin?key=<Render 里的 ADMIN_KEY>`，页面上的二维码就是正式二维码
2. **用微信扫一下**：应该直接进到点歌页（不是"用浏览器打开"的提示）
3. 随便投一首，再点个 ♥
4. 手机横过来看 `/screen`，二维码能扫

## 自己在电脑上跑（局域网，不注册任何账号）

需要 Node.js 18+（<https://nodejs.org>）：

```bash
cd song-box
npm start
```

打开 <http://localhost:8787>。二维码会自动指向你电脑的局域网 IP，同一个 Wi-Fi 下手机能扫。

> 注意：局域网是 http，微信里可能提示"非官方网页"，扫码也能打开；想给全班用还是走上面的云端方案。

## 部署到自己的服务器 / VPS（最稳，也最快）

```bash
docker build -t song-box .
docker run -d -p 8080:8080 -v songbox:/data -e ADMIN_KEY=换成你的密钥 song-box
```

HTTPS 用 Caddy / Nginx + 证书包一层即可（微信只认 https）。

## 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `8787` | 端口（云平台自动注入） |
| `HOST` | `0.0.0.0` | 监听地址 |
| `ADMIN_KEY` | 随机并打印 | 后台密钥，**上线后固定一个** |
| `PUBLIC_URL` | 按请求头推断 | 二维码指向的地址，如 `https://song.school.cn` |
| `DATA_DIR` | `./data` | 本地 JSON 数据目录 |
| `MAX_PER_HOUR` | `15` | **每台手机**每小时投稿上限 |
| `MAX_PER_IP_HOUR` | `300` | **每个 IP** 每小时上限（一个班常共用校园网出口 IP，所以放得很宽） |
| `UPSTASH_REDIS_REST_URL` / `_TOKEN` | — | 配了就走云端存储 |

## 数据与隐私

- 只存：歌名、歌手、随机匿名编号、时间、点赞数
- 不存姓名、手机号，**IP 不入库**（只在内存里做限流）
- 点赞去重靠浏览器随机设备号，只保存它的 12 位哈希
- 页面带 `noindex`，不会被搜索引擎收录

## 常见问题

**微信里打开是白屏 / 一直转圈？**
1. 确认链接是 `https://`（后台"复制链接"拿到的就是）
2. 免费实例可能刚休眠，等 20～30 秒再刷一次
3. 学校 Wi-Fi 有认证 / 屏蔽？换 4G 试

> 想彻底避开冷启动：注册一个免费的 UptimeRobot，每 5 分钟 ping 一次 `/healthz`，
> 实例就一直醒着（750 小时/月 ≈ 31 天，够用）。

**免费额度用完了会扣钱吗？**
不会。Render 的免费实例用满 750 小时后服务会暂停到下个月；Upstash 不绑卡时用超了是限流。
两边都不会自动转成付费、也不会产生账单。

**二维码扫出来是 localhost？**
说明是在本机打开的页面。用域名打开后台再看二维码，或设 `PUBLIC_URL`。

**被同学刷屏？**
限流是**按手机**算的（每台每小时 15 条），所以全班几十个人同一个校园网 IP 也互不影响；后台还能下架、删除，或临时关闭投稿。

**会不会有人狂点刷榜？**
同一台手机对同一首歌只能点一次（再点就是取消），换设备才可能重复。真遇到恶意刷榜，后台可以直接下架那首。

**可以只让本班人访问吗？**
目前靠"链接不外传"。如果担心外班乱投，可以加个访问口令 —— 需要的话告诉我，我加上。

**不想折腾 GitHub / Render？**
两个替代方案：
1. **自己的电脑 + 内网穿透**：本机 `npm start`，再用 cpolar / ngrok 之类的免费隧道把 8787 映射成 https 地址，二维码就用隧道给的网址（缺点：电脑得一直开着，免费隧道每次重启网址会变）。
2. **VPS / 云服务器**：`docker run`（见上文），配好 HTTPS 证书最稳、最快。

**想改标题？**
后台 → 设置，学生端、大屏、海报同步生效。

```
├── tools/                  # 三组自检
├── render.yaml             # Render 一键部署
└── Dockerfile
```
